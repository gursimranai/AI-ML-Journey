## 🛠️ Project Development Workflow

For each future project:

1. **Define the problem:** Explain what the program should accomplish.
2. **Plan the solution:** Identify inputs, outputs, and required concepts.
3. **Implement the code:** Write the program in manageable steps.
4. **Test the program:** Check normal cases, invalid inputs, and edge cases.
5. **Improve the design:** Refactor repeated code and improve readability.
6. **Document the project:** Explain its purpose, usage, and limitations.
7. **Publish the work:** Commit the tested code to the repository.

## 📁 Recommended Structure for Each Project

```text
project-name/
├── README.md
├── main.py
├── examples/
└── tests/
```

Use only the files and folders that a particular project needs. For very small projects, a `README.md` and a single Python file may be sufficient.

Each project README should explain:

- Project overview and purpose
- Features
- Python concepts demonstrated
- Requirements and setup
- How to run the program
- Example usage and output
- Testing and known limitations
- Sources and acknowledgements, if applicable

## 📌 Project Standards

- Write code that you understand and can explain.
- Use meaningful names and consistent formatting.
- Handle invalid inputs appropriately.
- Avoid exposing API keys, credentials, or private data.
- Credit external code, tutorials, and learning resources.
- Include tests when they provide meaningful value.
- Do not mark a project complete until its documented features have been implemented and tested.
