# 📸 Project Screenshots

This folder contains screenshots and visual previews of projects developed throughout the **AI-ML-Journey** repository.

These screenshots provide a quick overview of project interfaces, outputs, visualizations, workflows, and results. They can also be used in project documentation, GitHub READMEs, portfolios, and presentations.

## 🎯 Purpose

Project screenshots help demonstrate what a project does and how its output looks without requiring someone to run the code immediately.

They can be used to:

- Showcase project interfaces and features.
- Display model predictions and results.
- Present data analysis and visualizations.
- Document project progress and improvements.
- Enhance GitHub project READMEs.
- Support portfolio and internship applications.

## 📂 What to Store Here

Organize screenshots by project so that each project's visual assets remain easy to find.

Recommended structure:

```text
09-Project-Screenshots/
├── README.md
├── Anshika-AI/
│   └── .gitkeep
├── Aladdin-Analyst-AI/
│   └── .gitkeep
└── Other-Projects/
    └── .gitkeep
```

Replace or expand these example project folders as your actual projects grow. Keep each project's screenshots together rather than mixing unrelated images in one directory.

## 🖼️ Screenshot Guidelines

- Capture meaningful screens, outputs, or features.
- Use clear and descriptive filenames in **kebab-case**.
- Prefer PNG for interface screenshots and charts; use WebP or JPEG when appropriate.
- Crop unnecessary blank areas and avoid unreadable text.
- Use consistent dimensions when comparing multiple versions.
- Remove personal information, API keys, tokens, passwords, and other secrets before committing.
- Avoid including private user data or sensitive information in screenshots.

## 🏷️ Naming Convention

Use filenames that describe the project's feature or the result being demonstrated.

Examples:

- `project-dashboard.png`
- `data-cleaning-output.png`
- `exploratory-data-analysis.png`
- `model-training-results.png`
- `model-evaluation-metrics.png`
- `prediction-interface.png`
- `project-homepage.png`

For screenshots showing a sequence, use numbered names such as `01-homepage.png`, `02-data-upload.png`, and `03-results.png`.

## 🔗 Using Screenshots in a Project README

Reference a screenshot using a relative path from the Markdown file.

Example, when a project README is located in `11-Projects/Anshika-AI/README.md`:

```markdown
![Project interface](../../14-Assets/09-Project-Screenshots/Anshika-AI/project-dashboard.png)
```

**Tip:** For project-specific images, keeping screenshots inside the project directory can also be convenient. Use this shared folder when you want a centralized collection of project visuals.

## 📝 Best Practices

- Keep screenshots up to date with the actual project.
- Do not use mock screenshots to imply that unfinished features are working.
- Include a short caption or explanation when the image needs context.
- Prefer a few high-quality screenshots over many repetitive images.
- Ensure every screenshot matches the current project version.
