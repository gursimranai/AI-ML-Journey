# 🔀 Flowcharts

This directory contains flowcharts that represent processes, algorithms, decision paths, and step-by-step workflows visually.

Flowcharts help explain how a process works, how decisions affect execution, and how different steps connect from beginning to end.

## 🎯 Purpose

- Visualize algorithm execution and program logic.
- Represent decision-making processes and conditional branches.
- Explain step-by-step workflows.
- Illustrate data-processing and machine learning pipelines.
- Make complex procedures easier to understand and document.

## 🗂️ What Belongs Here?

Use this folder for:

- Algorithm flowcharts.
- Decision trees and branching workflows used to explain processes.
- Program execution flow diagrams.
- Data preparation and preprocessing workflows.
- Machine learning training and inference pipelines.
- Step-by-step procedural diagrams.

**Distinction:** Use `01-Diagrams/` for conceptual relationships and structures. Use `02-Flowcharts/` when the main purpose is to show the sequence of steps or decisions in a process.

## 📝 Naming Guidelines

Use descriptive filenames in kebab-case.

Examples:

- `Python-Program-Execution-Flow.png`
- `Conditional-Statements-Flowchart.png`
- `Data-Preprocessing-Workflow.png`
- `Machine-Learning-Pipeline.png`
- `Algorithm-Decision-Flow.png`

Use filenames that describe the actual content of each flowchart.

## 🔗 Using Flowcharts in Markdown

Reference flowcharts from notebooks or documentation using relative paths.

For example, from `01-Python/01-Fundamentals/01-Notebooks/`:

```markdown
![Conditional Statements Flowchart](../../../14-Assets/02-Flowcharts/Conditional-Statements-Flowchart.png)
```

Adjust the relative path and filename to match the actual location of the image.

## ✅ Best Practices

- Use clear starting and ending points.
- Keep the direction of the workflow consistent.
- Label decision branches clearly, such as **Yes** and **No**.
- Avoid unnecessary crossings and overly complicated layouts.
- Use consistent shapes and meaningful labels.
- Keep text readable at typical notebook and README display sizes.
- Preserve source attribution and licensing information when required.
- Update this README when important flowcharts are added or removed.

---

**Goal:** Make algorithms, decisions, and workflows easier to follow through clear visual representations.
